## Pitch

### Problem

TennisVideoHub 已经有 Django 项目骨架和一套上传业务的数据设计，但还没有任何可操作的产品流程。当前用户访问网站后，不能上传、保存或观看网球视频。过去的工作主要停留在模型设计文档，产品负责人无法通过真实使用判断方向是否正确。

### Baseline

- 指定开发环境可以运行 Python 3.10.20 和 Django 5.2.16。
- `manage.py check` 通过，Django 自带迁移已应用。
- `videos` 的 Model、View、URL 和 Test 仍是空壳。
- `/videos/` 没有可用页面。
- 没有业务模型、业务迁移、上传表单、详情页和媒体文件配置。

### Appetite

这是一笔最多一周的 Small Bet。目标是在 Appetite 内交付完整用户路径，而不是完成理想化的视频平台基础设施。

等待产品负责人验收或回答产品问题的时间不计入工程 Appetite。

### Payout

Bet 成功后，一名本地已登录用户可以：

1. 打开上传页面；
2. 选择一个不超过 50 MB 的 MP4 网球视频；
3. 填写场上人数、相机是否晃动、拍摄视角和标签；
4. 提交并保存视频；
5. 自动进入详情页；
6. 在浏览器中看到填写的信息并播放该视频。

这是 TennisVideoHub 第一条真实、可点击、贯通界面与数据库的产品纵向切片。

### Solution

- 复用 Django 自带用户模型和登录能力。
- 创建 `Video` 与 `Tag` 业务模型及迁移。
- 使用数据迁移预置“拉球”“比赛”“多球练习”三个标签。
- 使用 Django ModelForm 实现上传和业务字段验证。
- 在开发环境中将文件保存到本地 `media/` 目录。
- 上传成功后跳转到视频详情页。
- 详情页使用浏览器原生 `<video controls>` 播放 MP4。
- 上传页、详情页和登录页只做清楚可用的基础样式。
- 为核心成功路径、验证失败和登录限制建立自动化测试。
- 补充可重复的本地启动与验收说明。

### Rabbit Holes

1. **浏览器播放兼容性**：`.mp4` 只是容器格式，内部编码仍可能导致浏览器无法播放。本 Bet 只保证使用验收样例的浏览器可播放 MP4，不做转码。
2. **文件上传与开发媒体服务**：必须验证 multipart 表单、文件落盘、媒体 URL 和开发环境访问能完整贯通。
3. **登录入口**：项目已有 Django 用户系统，但没有面向用户的登录页面，需要建立最小登录流程。
4. **文件校验**：扩展名和大小可以在本 Bet 内可靠限制；完整识别伪装文件或视频编码需要额外工具，不进入本 Bet。
5. **环境复现**：指定 Conda 环境当前可运行，但仓库尚无依赖清单，需要留下最小可重复启动说明。
6. **媒体隐私**：开发环境直接提供媒体文件，不代表生产环境已经具备私有文件存储和授权下载能力。

### No-gos

本 Bet 明确不做：

- 2 GB 大文件上传；
- 视频转码、压缩或编码兼容处理；
- 自动提取时长、分辨率、帧率、容器或编码信息；
- 缩略图和视频预览生成；
- 上传进度条、分片上传、断点续传和后台任务；
- 云存储、CDN 和生产部署；
- 公共分享、视频列表、搜索、推荐和评论；
- 用户注册、找回密码和完整账号系统；
- 精细视觉设计和移动端专项优化。
